# TrainingPlan - Triathlon Training Management System

## Project Overview
TrainingPlan is a self-hosted, comprehensive training management platform for triathlon and running athletes. The system provides training plan management, workout tracking, integration with popular fitness platforms, and detailed progress analytics - all running locally on a QNAP NAS with mobile access.

## Core Objectives
1. **Training Plan Management**: Create and manage individualized training plans for triathlon (swim, bike, run) and running
2. **Device Integration**: Connect to Garmin Connect for automatic activity sync
3. **Platform Interoperability**: Import/export training plans from TrainingPeaks, import Strava activities, and support proprietary formats
4. **Self-Hosted Analytics**: Provide comprehensive training analytics similar to TrainingPeaks, Strava, WHOOP, TriDots
5. **Mobile Access**: Responsive web interface and/or native mobile app for on-the-go access

## Target Architecture

### Backend Stack
- **Runtime**: Python 3.11+ or Node.js 20+ (Python recommended for ML/analytics capabilities)
- **Framework**: FastAPI (Python) or NestJS (Node.js)
- **Database**: PostgreSQL 15+ (relational data) + TimescaleDB extension (time-series workout data)
- **Cache**: Redis (session management, API rate limiting)
- **Task Queue**: Celery (Python) or Bull (Node.js) for background jobs (sync, calculations)
- **Deployment**: Docker Compose on QNAP Container Station

### Frontend Stack
- **Web UI**: React 18+ with TypeScript
- **State Management**: Zustand or Redux Toolkit
- **UI Framework**: Material-UI (MUI) or Chakra UI
- **Charts/Visualization**: Chart.js or Recharts
- **Mobile**: Progressive Web App (PWA) first, React Native if needed

### Integration Layer
- **Garmin**: Garmin Connect API (OAuth2)
- **TrainingPeaks**: TrainingPeaks API v2
- **Strava**: Strava API v3 (activities import)
- **File Formats**: TCX, FIT, GPX parsers

### Infrastructure
- **Reverse Proxy**: Traefik or Nginx
- **SSL/TLS**: Let's Encrypt via Traefik
- **Backup**: Automated PostgreSQL dumps + Docker volume backups
- **Monitoring**: Prometheus + Grafana (optional)

## Key Features Breakdown

### Training Plans
- Multi-sport plan support (swim, bike, run, strength)
- Structured workouts with intervals and zones
- Template library (base, build, peak, taper phases)
- Plan duplication and versioning
- Drag-and-drop scheduling
- Recurring workouts

### Workout Types
- **Running**: Easy, tempo, intervals, long run, recovery
- **Cycling**: Endurance, sweet spot, threshold, VO2max
- **Swimming**: Technique, endurance, speed work
- **Strength**: Core, weights, flexibility
- **Brick**: Multi-sport sessions

### Activity Data
- Time, distance, pace/speed
- Heart rate zones and analysis
- Power data (cycling)
- Elevation/climbing
- GPS tracks and maps
- Lap/interval splits
- Equipment tracking

### Analytics
- Acute Training Load (ATL) - 7-day average
- Chronic Training Load (CTL) - 42-day average
- Training Stress Balance (TSB) = CTL - ATL
- Training Impulse (TRIMP)
- Form/Fitness/Fatigue chart
- Volume by sport and zone
- Personal bests and records

## Technical Considerations

### Performance
- Use database indexing on frequently queried fields (user_id, date ranges)
- Implement API response caching for analytics (Redis)
- Paginate large activity lists
- Lazy load images and charts
- Use connection pooling for database

### Security
- Store API credentials encrypted (Fernet or similar)
- Use environment variables for sensitive config
- Implement rate limiting on API endpoints
- HTTPS only (force redirect)
- CSRF protection
- Input validation and sanitization

### Data Privacy
- Self-hosted = user controls their data
- GDPR-compliant data export
- Secure credential storage
- Optional activity visibility controls

### Scalability
- Design for single user but allow multi-user
- Use message queue for long-running tasks
- Stateless API design
- Docker Compose can scale services if needed

## Development Guidelines

### Code Quality
- **Python**: Follow PEP 8, use type hints, docstrings
- **TypeScript**: Strict mode, explicit types
- **Testing**: Unit tests for services, integration tests for APIs
- **Linting**: Ruff/Black (Python), ESLint/Prettier (TypeScript)
- **Git**: Feature branches, conventional commits

### API Design
- RESTful endpoints with standard HTTP methods
- Consistent response format: `{data, error, meta}`
- Use HTTP status codes correctly
- API versioning (/api/v1/)
- OpenAPI/Swagger documentation

### Database
- Use migrations (Alembic for Python, Prisma/TypeORM for Node.js)
- Foreign key constraints
- Indexes on query-heavy columns
- Separate tables for time-series data

### Error Handling
- Graceful degradation when integrations fail
- Retry logic for external APIs
- User-friendly error messages
- Comprehensive logging

## Integration Notes

### Garmin Connect
- OAuth 2.0 with PKCE
- Rate limits: ~100 requests/hour
- Activity types: running, cycling, swimming, multisport
- Real-time sync not available (webhook not supported for personal apps)

### TrainingPeaks API
- API key required (paid account)
- Endpoints: workouts, workout library, athlete data
- TSS calculation supported
- Export format: JSON or ICS

### Strava API
- OAuth 2.0
- Rate limits: 100 requests/15min, 1000/day
- Activity data: detailed metrics, streams (lat/lng, HR, power)
- Webhook available for real-time updates
